# 图文敏捷开发文档模板体系
> **版本**：v1.0  
> **设计理念**：文字传递逻辑，图片传递上下文，二者互补形成完整认知  
> **适用场景**：Scrum 敏捷团队，强调可视化协作与快速对齐

---

## 模板一：产品愿景板 (Product Vision Board)

> **使用时机**：项目启动、每季度规划、新成员 onboarding  
> **核心原则**：一张图讲清"为谁、解决什么、凭什么"

---

### 【文字区】产品愿景陈述

```markdown
## 产品愿景

**我们为** [目标用户画像，附用户照片/头像]  
**解决** [核心痛点，附痛点场景照片/截图]  
**通过** [解决方案一句话描述]  
**实现** [成功后的理想状态，附愿景概念图/插画]

### 愿景验证指标
- 指标1：[文字描述] → 目标值：[数字] → 验证方式：[文字+图表类型]
- 指标2：...
```

### 【图片区】愿景可视化模板

```markdown

<!-- 4-6 格漫画式场景图，展示用户当前痛点 -->
```

## 模板二：用户故事可视化卡 (Visual User Story)

> **使用时机**：Sprint 计划会、Backlog 梳理、需求评审  
> **核心原则**：文字定义"做什么"，图片定义"长什么样、怎么交互"

---

### 【文字区】用户故事标准格式

```markdown
## 故事编号：US-XXX

**作为** [角色，附角色图标/头像]  
**我希望** [功能/能力]  
**以便** [业务价值/目的]

### 验收标准 (AC)
- [ ] AC1：文字描述 + 对应界面截图/状态标注
- [ ] AC2：...

### 优先级：[P0/P1/P2] | 故事点：[?] | 依赖：[US-YYY]
```

### 【图片区】故事可视化四件套

```markdown
### 1. 用户旅程流程图 (User Journey Flow)
<!-- 展示用户完成此故事的完整步骤和情绪曲线 -->
![用户旅程占位](sandbox:///mnt/agents/images/user-journey-placeholder.png)
*格式：横向时间轴，每步包含：步骤编号 + 界面缩略图 + 用户操作 + 情绪图标(😊/😐/😠)*

### 2. 界面原型/设计稿 (UI Mockup)
<!-- 此故事涉及的所有界面状态 -->
![界面原型占位](sandbox:///mnt/agents/images/ui-mockup-placeholder.png)
*格式：Figma/Sketch 导出，标注关键交互点，包含：正常态/加载态/空态/错误态*

### 3. 业务规则状态图 (State Diagram)
<!-- 展示实体状态流转或判断逻辑 -->
![状态图占位](sandbox:///mnt/agents/images/state-diagram-placeholder.png)
*格式：UML 状态图或简化流程图，标注状态转换条件和触发事件*

### 4. 数据/接口契约图 (Data Contract Diagram)
<!-- 展示输入输出数据结构或接口调用链 -->
![数据契约占位](sandbox:///mnt/agents/images/data-contract-placeholder.png)
*格式：JSON 结构截图 + 接口调用时序缩略图*
```

### 示例：Agent 技术设计文档

---

**【文字】**

### 2. 方案对比

| 方案 | 架构 | 优点 | 缺点 | 决策 |
|------|------|------|------|------|
| A：单体 ReAct | [图：单循环图] | 简单，易调试 | 无法处理多轮复杂逻辑 | ❌ 放弃 |
| B：LangGraph 状态机 | [图：多节点状态图] | 支持循环、状态持久化、可视化 | 学习成本略高 | ✅ 选中 |

### 3. 详细设计

**3.1 架构设计**  
采用 LangGraph 状态机编排 Agent 工作流。用户提问进入 Router 节点，根据意图分发至 RAG 检索、工具调用或人工转接节点，最终由生成节点输出带引用标记的回答。

**3.2 接口契约**  
Agent 对外暴露统一 Chat API：`POST /api/v1/chat`（附：Swagger 截图 + 请求/响应 JSON 示例）

## 模板七：发布手册图文版 (Visual Release Runbook)

> **使用时机**：生产发布、灰度放量、故障回滚  
> **核心原则**：一步一图，减少文字阅读成本，关键决策点用流程图标注

---

### 【文字区】发布手册结构

```markdown
## 发布手册：vX.X.X

### 1. 发布概览
- **版本**：vX.X.X
- **窗口**：YYYY-MM-DD HH:MM
- **内容**：X 个故事，Y 个缺陷修复，Z 个技术债务
- **风险等级**：[低/中/高]

### 2. 发布前检查清单
- [ ] 检查项1：[文字描述]
- [ ] ...

### 3. 发布步骤
步骤1：[文字操作] → 验证：[文字标准] → 回退条件：[文字]
步骤2：...

### 4. 回滚方案
[文字描述回滚触发条件和操作步骤]

### 5. 验证清单
- [ ] 验证项1：[文字]
- [ ] ...
```


### 图片质量要求
| 类型 | 格式 | 分辨率 | 大小限制 | 备注 |
|------|------|--------|---------|------|
| 界面截图 | PNG | 1920×1080 | ≤500KB | 关键区域红框标注 |
| 图表/流程图 | SVG/PNG | 矢量或高清 | ≤1MB | 文字清晰可读 |
| 照片 | JPG | 1920×1080 | ≤2MB | 适当压缩，关键信息可辨 |
| 原型/设计稿 | PNG | 按设计稿 | ≤1MB | 包含标注层 |

## 模板使用速查表

| 文档场景 | 主模板 | 核心图片 | 更新频率 |
|---------|--------|---------|---------|
| 项目启动 | 模板一：愿景板 | 用户画像+故事板+概念图 | 每季度 |
| 需求评审 | 模板二：故事卡 | 旅程图+原型+状态图 | 每Sprint |
| 每日站会 | 模板三：看板 | 看板截图+燃尽图 | 每日 |
| 技术评审 | 模板四：技术设计 | C4图+时序图+状态机 | 按需 |
| 发布前 | 模板五：评估报告 | 仪表盘+对比图+趋势图 | 每Sprint |
| Sprint结束 | 模板六：回顾纪要 | 现场照+情绪图+改进看板 | 每Sprint |
| 生产发布 | 模板七：发布手册 | 流程图+监控图+回滚指引 | 每版本 |

---

> **设计哲学**：在敏捷中，**文字负责精确，图片负责直观**。当团队需要"快速对齐"时看图，当需要"精确执行"时读文字。好的敏捷文档是"图文双通道"，让不同认知风格的人都能高效获取信息。
